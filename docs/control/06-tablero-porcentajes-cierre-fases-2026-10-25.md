## Reglas de cierre

1. Una fase se acepta **por su alcance explícito**, no por la finalización total de NETLAB360. Los componentes reaprovechados se registran en la fase que los implementó; no se exige repetirlos.
2. Una captura localizada por PowerShell no significa que se revisó visualmente; un fichero Markdown verificable de GitHub no es imagen PNG.
3. **Fase 1 72 % es un indicador histórico de matriz propia de 100 puntos; 90 % fases 2 y 3 son estimaciones de seguimiento no basadas en esa matriz.** No sumarlas ni promediarlas como métrica global.
4. Las evidencias GitHub se mantienen en `evidencias/capturas/fase1` a `fase8`, con `S01_` a `S08_` como prefijo. Para fase1 hay 86 PNG versionados vs 93 comunicados localmente. Ningún PNG fase2/fase3 se encontraba en GitHub al corte de reorganización; no prometer subirlos hasta recibirlos e inspeccionarlos.
5. Mantener el borrador `1457-Proyecto Semestral_borrador3.pdf` como última versión **79 páginas** de Word/PDF recibida. En este corte no incorpora aún la fase3 y todavía tiene figura1 en marcador de posición, tres referencias narrativas a «anexos» (págs.35,56,68), «S02» narrativo en págs.58,70 y una coma suelta en la introducción pág.6. No confundir esto con carencia técnica.
6. La docente aceptó entrega de código en archivo **TAR independiente**, no en sección de anexos Word. No imponer OVA.
7. La VM preserva state OpenTofu de fase3 fuera de Git y la fase2 se encuentra desmontada intencionalmente. **No recrear red ni repetir drift o apply solamente para capturas antes de auditar las imágenes existentes.**
