# Consulta del registro de notificaciones

El registro privado de Alertmanager permanece bajo su identidad de servicio. Exponemos un socket Unix administrado por systemd con acceso exclusivo a la cuenta web dedicada; cada conexión verifica las credenciales de proceso del par. El servidor ejecuta únicamente una consulta fija de alcance operacional o de validación, en modo SQLite de solo lectura, con límites de tiempo, tamaño y concurrencia. El archivo principal de la base se monta en solo lectura dentro de la unidad de consulta; el directorio permite la coordinación SQLite WAL. FastAPI no recibe permisos de archivo sobre esa base ni los secretos del receptor.

La API exige una sesión vigente. Las notificaciones operacionales son consultables por perfiles autorizados de lectura, y las validaciones sintéticas quedan reservadas al operador. Conservamos identidad, origen, activación, recepción y resolución; un registro vacío confirmado se distingue de una fuente inaccesible. El máximo de doscientas notificaciones recientes se presenta junto con el total y la indicación de truncamiento. No fusionamos ni sumamos automáticamente este registro con las observaciones históricas S04, puesto que representan fuentes y semánticas distintas.

El despliegue de aceptación instala unidades de ejecución transitorias en el directorio de configuración volátil de systemd y no reinicia Alertmanager, el receptor ni la consola oficial. Verificamos la lectura de ambos alcances y la denegación de acceso directo a la base desde la identidad web. La reconstrucción permanente deberá incorporar las plantillas, sus dependencias y las identidades ya aprovisionadas.
