# Adquisición continua de sondas

Ejecutamos Blackbox en los namespaces HQ y S2, con loopback exclusivo y CAP_NET_RAW solo donde el rango ICMP lo exige. Dos relés Unix sin capacidades reciben identificadores cerrados, verifican dirección de origen y ruta y consultan exclusivamente el exporter local. El gateway en 127.0.0.1:9116 ofrece cinco rutas de adquisición fijas. No expone la API genérica de Blackbox ni admite destinos, módulos o comandos arbitrarios. Los fallos de transporte producen HTTP 503 y no una métrica de fallo inventada.

El despliegue inicial instala una copia de código y binario verificados bajo un directorio propiedad de root, y crea cinco unidades transitorias. No instala paquetes de distribución ni habilita arranque automático; esa integración se valida en la recuperación de la plataforma. Prometheus reutiliza su unidad, TSDB y configuración existente. Conservamos el archivo anterior, validamos la configuración candidata con promtool y recargamos mediante SIGHUP, comprobando timestamp de recarga, seis targets, cuatro reglas S04 y tres reglas S08. Ante fallo se restaura la configuración anterior antes de detener las nuevas unidades; si no se confirma la restauración no se retiran fuentes requeridas por la configuración activa. Los directorios de diagnóstico se conservan.

Las ventanas iniciales pueden ser parciales: no se declara cumplimiento del objetivo por dos muestras. Se adquieren las series originales up y probe_success de Prometheus; la ausencia, fallo de adquisición y fallo medido se distinguen. Las nuevas reglas no tienen aún destino Alertmanager operacional. En el siguiente incremento conectaremos la entrega autorizada, persistencia de incidentes y lector de ventanas del portal. No se habilita una interfaz gráfica nueva.
